# code-comments

> **[CANONICAL.md](../CANONICAL.md) pins the symbols.** Table and column names,
> port and exception signatures, error codes, command shapes, migration order
> and interceptor priorities are declared there once. Where this file and
> CANONICAL.md disagree, CANONICAL.md wins and this file is a bug.

Comments and Javadoc exist for the non-obvious. Keep them concise and
professional: no "book" Javadoc, no decorative emojis, nothing that reads as
machine-generated filler. The code should look human-authored and clean.

## When to use

- Writing or reviewing any Javadoc, doc comment, or inline comment.
- Adding a log event name or an exception message.
- Reviewing a PR for comment noise or an "AI signature".

## The rules

1. **Document the WHY, not the WHAT.** The code already shows what it does; a
   comment earns its place only by explaining intent, a contract, an invariant,
   a trade-off, or a non-obvious gotcha. If it restates the code, delete it.
2. **Javadoc is concise.** A sentence or two on the purpose plus anything a
   caller genuinely must know (pre/postconditions, thrown domain exceptions,
   tenant/thread assumptions, money units, timezone assumptions). Never a
   paragraph per method, never a "book".
3. **No signature-echo tags.** Skip `@param` / `@return` / `@throws` that merely
   repeat the name and type. Add a tag only when it carries real information
   (units, bounds, nullability, currency, timezone, failure mode).
4. **Self-explanatory code needs no Javadoc.** A trivial getter, an obvious
   private helper, a clearly named method: none. Reserve Javadoc for public
   API, domain services, ports, and genuinely subtle logic.
5. **No emojis. Anywhere. Including logs.** Not in code, comments, Javadoc,
   exception messages, commit messages, and not as a status marker in a log
   line. Logs are structured JSON, parsed by machines and shipped to a log
   backend — an emoji is noise in a field, not a signal. Status belongs in the
   log LEVEL (`info`/`warn`/`error`) and in an explicit field
   (`outcome=success|failure`), which is greppable and machine-readable;
   a pictogram is neither. The code must never read as AI-generated.
6. **No decorative or generated noise.** No ASCII-art banners, no
   "Generated by ..." lines, no comment that just restates the class name, and
   no commented-out code left behind — delete it, git remembers.
7. **Comments, Javadoc, and log event names are English** (see
   `code-language`); user-facing text is never a code comment.

## Anti-patterns

- A 20-line Javadoc block on a 3-line method -> rule 2.
- `@param amount the amount` / `@return the result` -> rule 3.
- `// increment counter` above `counter++` -> rule 1.
- Any emoji in a log, comment, or Javadoc -> rule 5; use the log level and an
  `outcome` field instead of a pictogram.
- An emoji in code, an exception message, or a commit message -> rule 5.
- `/** ProviderService. A service for providers. */` -> rule 1 + rule 4.
- A block of commented-out old code kept "just in case" -> rule 6.

## Minimal correct example

```java
/**
 * Books an appointment on a concrete staff member. The end instant is
 * recomputed from the service duration and buffers; any end time sent by
 * the client is ignored. Exclusion is enforced by the database, so a
 * concurrent overlapping booking surfaces as SlotUnavailableException.
 * The customer price is frozen in minor units of the provider's currency
 * (GNF has scale 0).
 */
public Appointment book(BookAppointmentCommand command) { ... }
```

Purpose plus the three things a caller must know (server-recomputed slot,
database-enforced conflict, money units) — no tag noise, no emoji, no filler.

### Log status, without pictograms

The level carries the severity and a structured field carries the outcome, so
the line stays greppable and parseable — no emoji (see `pii-masking-logging`):

```java
// Structured fields via MDC; the message is a stable dotted event name, not a
// sentence with values baked in (see `pii-masking-logging` rules 1-2).
// appointment_id resolves to one customer, so it goes through maskId; the
// provider id and correlation id are bound raw at the boundary.
MDC.put("outcome", "success");
MDC.put("appointment_id", LogMasking.maskId(appointment.id()));
log.info("appointment.booked");

MDC.put("outcome", "failure");
log.warn("appointment.book.slot_unavailable");
```

## Sibling skills

- `code-language` — comments, Javadoc, and event names are English;
  user-facing text is French first, from the i18n catalogue.
- `backend-naming` — a precise name removes the need for a comment.
- `commit-style` — the no-emoji, professional rule applies to commit messages
  too.
- `pii-masking-logging` — what a log line may and may not carry, which
  identifiers are masked, and why the message is a dotted event name.
- `cdi-interceptors` — the log call itself belongs to the audit interceptor,
  not to the business method the Javadoc documents.
